# Ω Notes V2 — 项目是怎么建起来的

> 这篇笔记写给零基础的自己：从"什么都没有"到"一个能安装的桌面笔记软件"，到底经历了什么。

---

## 0. 先搞清楚一件事：软件到底是什么？

你手机上的微信、电脑上的 VS Code，本质上都是：

```
代码（程序员写的） → 编译（翻译成电脑能懂的） → 软件（你双击能用的）
```

我们做的这个笔记软件也一样，只不过我们从头开始写代码。

---

## 1. 选技术：我们用了什么工具？

想象你要盖一栋房子，你需要选择用什么材料、什么工具：

### 前端（你能看到的界面）

| 工具 | 是什么 | 为什么用它 | 类比 |
|------|--------|-----------|------|
| **Vue 3** | 界面框架 | 帮你把页面拆成一块一块的"组件"，方便管理 | 乐高积木系统 |
| **TypeScript** | 带类型的 JavaScript | 写代码时自动检查错误，减少 bug | 带拼写检查的打字机 |
| **Vite** | 构建工具 | 把你写的代码打包成浏览器能运行的文件，速度极快 | 高速编译器 |
| **Pinia** | 状态管理 | 集中管理所有数据（笔记列表、当前分类等） | 中央数据库 |
| **Vue Router** | 路由 | 控制页面跳转（首页→知识库→写笔记→笔记详情） | 导航地图 |

### 编辑器（你写笔记的地方）

| 工具 | 是什么 | 类比 |
|------|--------|------|
| **Milkdown** | 所见即所得的 Markdown 编辑器 | 像 Word 一样打字，但产出的是 Markdown 格式 |
| **markdown-it** | Markdown → HTML 渲染器 | 把 `# 标题` 变成真正的大字标题 |
| **KaTeX** | 数学公式渲染 | 把 `$E=mc^2$` 变成漂亮的数学公式 |
| **highlight.js** | 代码高亮 | 让代码块有颜色，像 VS Code 里那样 |

### 桌面壳（让网页变成"软件"）

| 工具 | 是什么 | 类比 |
|------|--------|------|
| **Tauri 2** | 桌面应用框架 | 给你的网页套一个"壳"，变成 .exe 软件 |
| **Rust** | 系统编程语言 | Tauri 的后端用 Rust 写，负责和操作系统打交道 |

### 一张图看全貌

```
┌─────────────────────────────────────────┐
│           你看到的界面 (前端)              │
│                                         │
│   Vue 3 组件 ──→ Milkdown 编辑器         │
│       ↕                                 │
│   Pinia Store ──→ 管理笔记数据           │
│       ↕                                 │
│   storage.ts ──→ 读写文件/localStorage   │
│                                         │
├─────────────────────────────────────────┤
│         Tauri 2 (桥梁)                   │
│   把前端打包进桌面窗口，提供系统 API       │
├─────────────────────────────────────────┤
│         Rust 后端                        │
│   系统托盘、文件读写、全局快捷键           │
└─────────────────────────────────────────┘
```

## 2. 项目是怎么一步步搭起来的？

### Phase 1：先搭骨架

就像盖房子先打地基、立柱子：

```
第1步：创建空项目
  npm create vue@latest    → 自动生成 Vue + Vite + TypeScript 项目模板

第2步：设计"长什么样"
  variables.css            → 定义所有颜色、间距、圆角（Design Token）
  reset.css                → 消灭浏览器自带的丑样式

第3步：做出基本页面
  AppHeader.vue            → 顶部导航栏
  AppSidebar.vue           → 侧边栏
  HomeView.vue             → 主页
  NotesView.vue            → 知识库页
  WriteView.vue            → 写笔记页
  NoteDetailView.vue       → 看笔记页

第4步：让数据动起来
  stores/notes.ts          → 笔记的增删改查
  stores/theme.ts          → 暗色/亮色主题切换
```

到这一步，你已经有了一个 **能在浏览器里跑的笔记网页**。

### Phase 2：让编辑器更强

```
第5步：接入 Milkdown 编辑器
  MilkdownEditor.vue       → 编辑器外壳
  MilkdownEditorCore.vue   → 编辑器核心（插件注册）

第6步：加数学公式
  @milkdown/plugin-math    → 编辑时渲染公式
  markdown-it-texmath      → 阅读时渲染公式
```

### Phase 3：从"网页"变成"软件"

这是最关键的一步：

```
第7步：加入 Tauri
  npm create tauri-app     → 在项目里加入 Rust 后端
  tauri.conf.json          → 配置窗口大小、应用名称等

第8步：文件持久化
  utils/storage.ts         → 笔记存成 .md 文件（而非浏览器缓存）

第9步：桌面专属功能
  utils/shortcuts.ts       → Ctrl+Shift+N 全局快捷键
  src-tauri/src/lib.rs     → 系统托盘（右下角小图标）

第10步：编译
  npm run tauri build      → 生成 .exe 安装包
```

## 3. 关键概念解释

### 什么是"组件"？

Vue 把界面拆成一个个小零件，叫做"组件"。比如：

```
整个应用 (App.vue)
├── 顶部栏 (AppHeader.vue)      ← 一个组件
├── 侧边栏 (AppSidebar.vue)     ← 一个组件
└── 页面内容 (HomeView.vue)      ← 一个组件
    ├── 统计卡片                  ← 可以继续拆成更小的组件
    └── 最近笔记列表
```

好处：每个组件只管自己那一小块，改一个不影响其他的。

### 什么是 Store（状态管理）？

想象一个共享白板：

- **白板** = Store（`stores/notes.ts`）
- **白板上的内容** = 数据（笔记列表、搜索关键词）
- **所有人都能看** = 任何组件都能读这些数据
- **统一修改** = 只能通过 Store 提供的方法改数据，不会乱

### 什么是 Tauri？

Tauri 做的事情很简单：

```
你的 Vue 网页  ──→  Tauri 套个窗口壳  ──→  变成 .exe 软件
                         │
                    同时提供系统能力：
                    - 读写文件
                    - 系统托盘
                    - 全局快捷键
                    - 等等...
```

类似的技术还有 Electron（VS Code 就是用 Electron 做的），但 Tauri 比 Electron **小得多**：

| 对比 | Electron | Tauri |
|------|----------|-------|
| 安装包大小 | ~150MB | ~5MB |
| 内存占用 | 高 | 低 |
| 后端语言 | JavaScript | Rust |

### V1 为什么"失败"了？

你的 V1 也是笔记软件，但有几个硬伤：

| 问题 | V1 的做法 | V2 的做法 |
|------|----------|----------|
| 代码维护 | 1200 行的 `ui.js` 手写 DOM，改一处全崩 | Vue 组件化，每个文件职责明确 |
| 数据安全 | IndexedDB，清缓存就没了 | .md 文件存硬盘，永不丢失 |
| 运行方式 | 只能开浏览器 | 独立桌面软件 + 手机也能跑 |
| 扩展性 | 加功能要改一大坨代码 | 加功能就是加一个组件 |

## 4. 手机端的情况

你提到"手机端也可以用，虽然笔记可能不是一致的"——说得对。

### 现状

```
电脑端  → 笔记存在电脑的 AppData 文件夹
手机端  → 笔记存在手机的 App 沙盒目录
```

两边的数据目前是 **各存各的，不互通**。

### 要实现同步怎么办？

以后如果想让电脑和手机的笔记一致，有几种方案：

| 方案 | 难度 | 说明 |
|------|------|------|
| **手动导出/导入** | ⭐ | 导出 .md 文件 → 发到手机 → 导入 |
| **局域网同步** | ⭐⭐ | 同一个 WiFi 下，电脑和手机自动同步 |
| **网盘同步** | ⭐⭐ | 笔记文件夹放在 OneDrive/坚果云里 |
| **自建服务器** | ⭐⭐⭐⭐ | 租个云服务器做中转，全自动同步 |

这些都是后续可以做的，现在先把基础功能做好。

## 5. 核心文件速查表

| 文件 | 用一句话说它干嘛 |
|------|-----------------|
| `src/main.ts` | 应用启动入口，把所有东西组装到一起 |
| `src/App.vue` | 根组件，定义整体布局（顶栏+侧栏+内容区） |
| `src/stores/notes.ts` | 管理所有笔记数据的"大脑" |
| `src/utils/storage.ts` | 决定笔记存到哪里（文件 or 浏览器缓存） |
| `src/utils/shortcuts.ts` | 注册全局快捷键 |
| `src/components/MilkdownEditor*.vue` | Markdown 编辑器 |
| `src/components/MarkdownRenderer.vue` | Markdown 阅读渲染 |
| `src/views/*.vue` | 各个页面 |
| `src/assets/styles/variables.css` | 所有颜色、间距等设计参数 |
| `src-tauri/src/lib.rs` | Rust 后端（系统托盘等） |
| `src-tauri/tauri.conf.json` | 应用的"身份证"（名字、窗口大小等） |

## 6. 常用命令

```bash
npm run dev          # 启动开发服务器（浏览器预览）
npm run tauri dev    # 启动桌面应用（带 Rust 后端）
npm run tauri build  # 编译成安装包（.exe）
npm run build        # 只编译前端（不含 Tauri）
```
