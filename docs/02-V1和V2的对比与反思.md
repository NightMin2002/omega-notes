# Ω Notes V2 — V1 vs V2 对比与反思

> 为什么 V1 走不下去了？V2 换了什么方向？这篇笔记记录两代架构的差异和背后的思考。

---

## V1 长什么样？

V1 是一个纯浏览器笔记应用，所有代码都是手写的原生 JavaScript：

```
omega-v1/
├── index.html           ← 唯一的入口
├── css/
│   ├── variables.css    ← 这个设计得不错，V2 沿用了思路
│   ├── reset.css
│   └── modules/         ← CSS 模块化，这个也不错
├── js/
│   ├── ui.js            ← 1200+ 行的 DOM 操作，灾难的起点
│   ├── state.js         ← 简陋的状态管理
│   ├── controllers/     ← 各种业务逻辑
│   └── markdown/        ← 自己集成的 Markdown 解析
└── (没有构建工具，直接 <script> 引入)
```

## V1 做对了什么？

| 亮点 | 说明 |
|------|------|
| **CSS 设计系统** | `variables.css` 用 CSS 变量定义颜色、间距，思路超前 |
| **模块化 CSS** | 按功能拆分 CSS 文件（`modules/`），比一坨写在一个文件里好 |
| **暗色/亮色主题** | 很早就做了双主题切换 |
| **功能完整度** | 笔记 CRUD、分类、搜索、AI 对话，功能不少 |

## V1 哪里崩了？

### 问题 1：`ui.js` 1200 行的地狱

```javascript
// V1 的写法：手动操作 DOM
function renderNoteCard(note) {
  const card = document.createElement('div')
  card.className = 'note-card'
  const title = document.createElement('h3')
  title.textContent = note.title
  card.appendChild(title)
  // ... 还有几十行这样的代码，就为了画一张卡片
  // 如果要改卡片布局？从这几十行里找，改错一行全崩
}
```

```vue
<!-- V2 的写法：Vue 模板，一目了然 -->
<div class="note-card">
  <h3>{{ note.title }}</h3>
  <p>{{ note.content }}</p>
</div>
<!-- 改布局？直接改 HTML 结构就行 -->
```

**教训**：手写 DOM 操作在代码少的时候很爽，代码多了就是维护噩梦。

### 问题 2：状态散落各处

```javascript
// V1：数据到处都在改
// controllers/noteController.js 里改一下
state.notes.push(newNote)
// ui.js 里又改一下
document.querySelector('.counter').textContent = state.notes.length
// 另一个文件里又改一下...
// 结果：改了一个地方，忘了更新另一个地方 → bug
```

```typescript
// V2：所有数据操作都在 Store 里，只有一个入口
const notesStore = useNotesStore()
notesStore.addNote({ title: '新笔记', content: '...' })
// 所有用到笔记数据的地方自动更新，不可能漏
```

**教训**：数据要有唯一的管理者，不能散落在各个文件里。

### 问题 3：数据会丢

```
V1：笔记 → IndexedDB（浏览器数据库）
     ↓
     清除浏览器缓存 → 全没了 💀
     换个浏览器 → 看不到了 💀
```

```
V2：笔记 → .md 文件（硬盘上的真实文件）
     ↓
     清缓存？无所谓，文件还在 ✅
     换浏览器？无所谓，文件还在 ✅
     换电脑？拷贝文件夹就行 ✅
```

### 问题 4：只能在浏览器里用

V1 没有桌面壳，只能：
1. 打开浏览器
2. 打开 `index.html`
3. 使用

V2 有 Tauri，直接双击图标就能用，还有系统托盘和全局快捷键。

## V2 的方向为什么更好？

| 维度 | 分析 |
|------|------|
| **可维护性** | 组件化 → 每个文件几十到一百多行，好懂好改 |
| **可扩展性** | 加功能 = 加组件 + 加路由 + 加 Store，不影响现有代码 |
| **跨平台** | 同一套代码 → 桌面（Win/Mac/Linux）+ 手机（Android/iOS） |
| **数据安全** | .md 文件在硬盘上，标准格式，永远可读 |
| **生态** | Vue/Tauri 有庞大社区，遇到问题能搜到答案 |

---

## 思维转变

| 旧想法 | 新认知 |
|--------|--------|
| "自己从零手写最牛" | 用成熟框架不丢人，省下的时间用来做功能 |
| "浏览器就够了" | 桌面应用的体验（快捷键、托盘、文件系统）是浏览器做不到的 |
| "数据存浏览器就行" | 用户的数据必须存在用户能掌控的地方（文件系统） |
| "能跑就行" | TypeScript 的类型检查能在编译时抓住 bug，而非运行时崩溃 |
